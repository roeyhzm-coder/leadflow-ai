# LeadFlow AI

Multi-tenant WhatsApp AI sales and lead capture dashboard. React + Vite frontend, Vercel serverless API, Supabase, and Gemini.

## Setup

1. Copy `.env.example` to `.env` and fill in keys.
2. In the Supabase SQL editor run `supabase/schema.sql` (fresh projects only), then `supabase/apply-all.sql` — the rate-limit RPC and the enterprise migration in one idempotent transaction (generated by `npm run sql:bundle` from `supabase/rate-limit.sql` and `supabase/migrations/`). Until it runs, the webhook uses an in-memory rate limit, night mode and the strict price list are off, and the dashboard cannot load (no `tenant_members` table).
3. Dashboard access (Supabase Auth): under Authentication → Providers keep Email enabled and turn off "Allow new users to sign up"; under URL Configuration set the Site URL / redirect URLs to the dashboard origin (needed for magic links). Create or invite each user under Authentication → Users, then add a `tenant_members` row (template at the end of `apply-all.sql`). Owners can edit settings; staff are read-only on settings. Emails in `PLATFORM_ADMIN_EMAILS` may create tenants and change WhatsApp routing fields.
4. Point your Green API webhook to `https://<your-domain>/api/webhook`.
5. `npm install` then `npm run dev` for the dashboard, or deploy to Vercel.

With `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` set, the dashboard requires sign-in and reads data only through `/api` with the session's JWT (`/api/leads` and `/api/tenants` answer 401 without one and scope every query to the caller's `tenant_members`). Without them it runs on local demo data.

## Bot pipeline (`api/webhook.ts`)

Per incoming message: tenant routing (Green API `instanceId`, then recipient phone) → idempotency (`messages.raw_message_id`, unique) → human-takeover mute (a staff reply from the clinic device mutes the bot for 24h) → rate limit (5/min per customer, 60/min per tenant, HTTP 429 + `Retry-After`) → prompt-injection pre-filter → human-handoff request → business hours (first off-hours message gets the night greeting; follow-ups run the AI in after-hours mode) → Gemini (`temperature 0.2`, `maxOutputTokens 250`, last 8 messages) → output guard (unlisted prices, prompt/secret leaks) → lead upsert (one open lead per conversation, fields merged across turns, staff notified once when name + treatment + time are known). If Gemini fails, the customer gets "הודעתך התקבלה, נציג יחזור אליך בהקדם" and staff are alerted.

Tenant config lives in `tenants.business_hours`, `price_list`, `faq`, `notification_phone` (editable via `PATCH /api/tenants`).

## Tests

- `npm test` runs offline and deterministic (stubbed Gemini, in-memory store, no paid calls).
- `npm run test:live` also hits real Gemini and Supabase (paid; the lead test creates and deletes a throwaway inactive tenant).
- `npx tsx scripts/test-api-auth.ts --live [origin]` probes a deployed origin for 401s on the dashboard APIs.
